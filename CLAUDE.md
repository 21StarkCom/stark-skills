# CLAUDE.md — stark-skills

## What This Is

The stark skills + tools fleet: a **two-stage development pipeline** (`/stark-author` human-gated spec+plan → `/stark-build` check-gated implementation — no LLM-reviews-LLM loops, per the 2026-07-25 autopsy and the 2026-07-26 demolition), a **single-agent PR code reviewer** (`/stark-review`, evidence-contract prompts), multi-agent IaC review, and the ops/session tier. Claude, Codex, and Gemini are all enabled (Gemini → `gemini-3.1-pro-preview`, default auth **oauth** — the logged-in Google account's Code Assist seat; `vertex` and `api-key` modes remain via `models.gemini.auth` / `STARK_GEMINI_AUTH`, see `tools/gemini_auth_lib.ts`). The Vertex **project/location are resolved at runtime** by `tools/vertex_config_lib.ts` (env > config > `GOOGLE_CLOUD_PROJECT` > local `gcloud`) — **never hardcoded/committed in source**; in oauth mode the resolved project doubles as the Code Assist licensing project. Note: `-latest` aliases like `gemini-pro-latest` only resolve via the Generative-Language API-key fallback, **not** Vertex. Hierarchical config (global → org → repo). Self-improving prompts via review history analysis.

## Operating Principles

This is a **personal playground**, not production. No customers depend on it; the only user is the author.

- **No rollout ceremony.** Skip soaking, gating, smoking, canary, and gradual-rollout patterns. Merge straight to main once the PR is green.
- **Branch + PR for everything — nothing lost.** Every change lands on a branch and merges via PR; never commit or push to `main` directly. "Ship straight to main" means merge once green, not bypass the PR. This repo **is** the review system — so every review's findings get posted on the PR as comments (inline where anchored, summary otherwise; `stark_review.ts` already does the GitHub posting). Don't drop, downgrade, or summarize findings away, and don't merge with open findings unaddressed — fix them, or reply on the thread saying why not.
- **Every PR action is `aryeh-stark`; bots only post reviews.** Opening a PR, commenting as Aryeh, resolving a thread, un-drafting, merging, opening an issue — all go through the `gh` CLI, which is logged in as **`aryeh-stark`**. The `stark-{claude,codex,gemini}` GitHub Apps exist for **one** reason: posting multi-LLM review findings, where three distinct bot authors are what makes "which model said this" readable. `tools/github_app{,_lib}.ts` therefore exposes reads plus `pr review`/`pr comment` and **nothing that authors on Aryeh's behalf** — `pr create`, `pr ready`, `pr merge` and `issue create` were removed 2026-08-04 and now exit 2 naming the `gh` command to run. CI is the one exception, since a workflow has no human token (and Aryeh's PAT in Actions secrets would be worse): `marketplace-sync.yml` mints an app token and calls `gh pr create` with it.
  - **The one human-invoked swap: `/stark-gh-user`.** When `aryeh-stark`'s GraphQL/REST bucket runs dry, Aryeh can move `gh` to a relief account for the rate-limited command. It is his call, never an agent's — `disable-model-invocation: true`, and no tool, skill or hook may call `tools/user_token.ts`. Wiring it into an automated path would re-author whatever ran next, which is exactly the failure this rule exists to prevent. Default stays `primary` = `aryeh-stark`; revert with `unset GH_TOKEN GITHUB_TOKEN STARK_GH_USER` when the window closes.
- **Draft PRs by default — test locally, un-draft to merge.** Every PR-opening path opens a **draft** so WIP stays out of draft-guarded CI while you verify locally. The default is owned by the `gh` path — `plugins/stark-gh/tools/gh_pr_open_execute.ts` resolves it through the shared draft config so `pr-open` and `pr-merge` agree on one answer; the review/author/build skills pass `--draft` explicitly. Opt out per-run with `--ready` (alias `--no-draft`). **You cannot merge a draft**, so the merge paths un-draft first: `/stark-gh:pr-merge` (`gh pr ready`) marks the PR ready-for-review — which fires the target CI via the `ready_for_review` event — then wait for green, then squash-merge. For "no CI on WIP" to actually hold, each target repo's `pull_request` workflows need the **skip-draft guard** (`if: github.event.pull_request.draft == false` + `ready_for_review` in `types`) — pattern + `== false` vs `!= true` guidance in `standards/workflows/skip-draft-guard.md`. Exempt: push-triggered publishers like `marketplace-sync` that must run CI + auto-merge (they open ready).
  - **NEVER guard a workflow whose check is a required status check** (STARK-357). A guarded job reports `skipped`, GitHub counts `skipped` as *satisfying* a required check, and the merge box renders it identically to a pass — so the guard turns "CI did not run" into "CI is green". PR #877 merged that way on 2026-08-11: the only `pull_request` run on its head sha was the draft-time one, and the suite never executed against what landed. **There is no repair once it happens** — re-running replays the original payload (so it skips again), and a `workflow_dispatch` run **does not join the PR's status rollup** (measured: `test: SUCCESS` in `gh run list`, `test: SKIPPED` in the rollup every merge gate reads). Only a new commit clears it. `.github/workflows/tests.yml` is therefore deliberately unguarded (and carries `cancel-in-progress: false`, since an unguarded job is long enough for the un-draft to cancel the in-flight run and leave `test: CANCELLED` — which GitHub counts as *failing* — on the head sha), and it runs **both** suites — `tools/` (1705 tests) and `plugins/stark-gh/` (388), the latter having never run in CI at all until STARK-357 because `tools/`'s `*.test.ts` glob could not reach it.
  - **`/stark-gh:pr-merge` refuses a skipped required check**, more strictly than GitHub does, naming it and telling you to push a commit; `--allow-skipped-checks` opts back in for repos that skip a required check by design (path filters). Related: `lib/checks_graphql.ts` now collapses same-named rollup contexts to the **latest** before judging (GitHub's own semantics), so a stale green can no longer outvote a newer failure, and `required` counts checks rather than rollup rows.
- **Language preference:** Go for backend, TypeScript for scripts. **Avoid Python at all costs** — the repo's tooling is now TypeScript-only (`tools/`); the former Python orchestrators + dispatch infra under `scripts/` were migrated out. Do not introduce new Python.
- **Test live.** Local-only verification is not enough. If a flow touches GCP, exercise the real GCP surface.
- **Always update documentation.** Any change that affects behavior, structure, commands, env vars, or operations must update the relevant docs (this file and `AGENTS.md` included) in the same change.

## Distribution

This repo is the **source of truth** for the skills + tools. Distribution is **marketplace-only** — the former `install.sh` symlink installer was removed (2026-07-07); there is no local symlink install step.

- **bifrost** (the marketplace; formerly `stark-marketplace`, renamed 2026-07-11) — the `bifrost` repo packages these skills as separate self-contained Claude Code and native Codex plugins. Claude installs with `/plugin marketplace add 21StarkCom/bifrost` then `/plugin install <bundle>@bifrost`; Codex installs with `codex plugin marketplace add 21StarkCom/bifrost` then `codex plugin add <bundle>@bifrost`. Canonical `skill/`, `plugins/stark-gh/commands/`, and shared assets remain Claude-authored. Complete Codex variants live only under `runtime-overrides/codex/`, which Bifrost imports into a separate `dist/codex-plugins/` package surface; Codex overlays must never enter `dist/claude/`. CI auto-publishes changes to either source surface.
- **Local dev is no longer live.** Editing a file in this repo does not take effect until the change is published (merge to `main` → `marketplace-sync` PR → merge) and the plugin is reinstalled/updated (`/plugin update …`). To test an in-progress edit against a real install, run `stark sync` in the marketplace repo and `/plugin update` locally.
- **Assets plugins don't cover** (user `~/.claude/settings.json`, statusline, output-styles, `org/evinced` overrides, mutable-state dirs, git hooks) are now managed by hand — the installer no longer provisions them.
- **GCP worktree scope stays local and narrow.** `tools/gcp_scope.ts install` owns each mapped repo's generated `.envrc` block and the exact `.envrc` row in `.worktreeinclude`; `check` validates both. Other include rows and comments survive, and the tool never adds credentials or broad globs. Codex-managed worktrees consume `.worktreeinclude`; helpers that create plain Git worktrees must copy those named files themselves.

**The plugin-resolution seam:** `tools/asset_root_lib.ts` — `assetRoot()` resolves immutable assets (tools/prompts/config) from `${CLAUDE_PLUGIN_ROOT}` when running inside an installed plugin, falling back to `~/.claude/code-review` for direct (non-plugin) invocations through that symlink; `stateRoot()` always stays under `$HOME`. Skills mirror this with `${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/code-review}`. **Never hardcode `~/.claude/code-review/{tools,prompts,scripts,standards}` in a skill or tool** — route immutable-asset reads through `asset_root_lib`/the dual-fallback so plugin installs keep working.

## Key Files

### Dispatchers & orchestration
- `tools/copilot_land_lib.ts` (pure) + `tools/copilot_land.ts` (CLI) — `/stark-copilot`'s create-or-adopt **impl-PR landing** helper (`branch-name`/`prepare-branch`/`land`): deterministic `copilot/<slug>` branch, push never `--force`, adopt-or-open PR by head ref (draft by default, `--ready` un-drafts even an adopted draft via `gh pr ready`), multi-PR union. **`prepare-branch --require-base <sha>`** (added 2026-07-30) closes a silently-wrong-run class: with no local branch but an existing remote one, the adopt path runs `git checkout -B <branch> origin/<branch>`, which **resets HEAD onto the remote branch** — so a leftover branch from an abandoned run replaces the caller's pinned base with an older codebase while the tool still reports `ok: true`. Reproduced live on a `/stark-build` run (every gate would have measured a tree predating the re-pin). The flag refuses that adoption **before** the destructive checkout on **both** the `checkout-track` and `checkout-ff` paths (the worktree never moves — a stale *local* branch is as dangerous as a stale remote one) and re-asserts `HEAD` contains the base afterwards. Hardened 2026-07-30 after review: an **empty** value is rejected rather than silently disabling every guard; **unknown flags are a hard error** (`--requirebase` used to parse to a no-op and exit 0, so a typo disabled the guard invisibly); `--dry-run` evaluates the guard and reports `would_refuse` instead of green-lighting the case the real run refuses; and containment is **tri-state** — `merge-base --is-ancestor` exit 128 means *unresolvable* (a `--single-branch`/`--depth` clone never created `refs/remotes/origin/<branch>`), NOT stale, because collapsing the two told operators to delete healthy branches holding pushed work. **Both `/stark-build` Phase 1 and `/stark-copilot` §1.7 pass it** — copilot pins the current `HEAD` and its blast radius is larger, since it adopts into `$REPO_ROOT` rather than a throwaway worktree. Phase 1 additionally checks `prepare-branch`'s **exit code** and that HEAD is on the expected branch: a refusal leaves HEAD untouched, so a bare `merge-base --is-ancestor` compares the base to itself and passes.
- `tools/findings_review_post.ts` — publishes a Claude Code **`ReportFindings` payload to a PR as ONE anchored review**. CLI: `--repo O/R --pr N --findings <path|-> [--app claude|codex|gemini] [--dry-run]`. This is the mechanism behind "every review's findings get posted on the PR" — **never `gh pr comment`, never `/code-review --comment`**. The pathology it replaces: `--comment` posts one standalone `POST /pulls/N/comments` per finding and GitHub wraps each in its own **empty review object** — measured on kotodama#737 as **30 reviews, every one zero-body**. The tool is pure mapping plus a CLI over the existing `stark_review.ts::postReview` (one review, inline anchoring, three-tier no-drop), so it adds **zero** posting/retry/fallback logic. Three things are load-bearing: **`classification: "fix"` is set on every finding**, because `partitionInlineVsBody` requires it for inline eligibility and without it every finding silently lands in the body and nothing is ever anchored; **`fixThreshold: "low"`**, so severity filters nothing out; and **`posterToken` from `tokenForAgent(agent, {forceRefresh: true})`**, which makes the review land as `stark-<agent>[bot]` — a real **non-author** reviewer, since `gh` authenticates as `aryeh-stark`, usually the PR author, and GitHub forbids `APPROVE`/`REQUEST_CHANGES` on your own PR. **Anchors are validated per LINE, not per file** (STARK-329) — the fix for the defect the first release shipped. GitHub only accepts a comment on a line inside a diff hunk; the adapter originally checked only that the *file* was in the diff, so a finding pointing at an unchanged line reached the API, which **422s naming no index**, and `postReview`'s conservative fallback then posts body-only — demoting **every** valid anchor in the batch with it. Measured on PR #870: three of four anchors sat in valid hunks and none survived. `anchorableLinesFromPatch` now walks each file's patch and collects the right-side line numbers (context + added lines; deleted lines are left-side and unaddressable), and a finding outside every hunk has its `line` dropped client-side with `**Location:** file:line (outside this PR's diff)` prepended to its body instead — so it lands in the review body with its location intact and costs no other finding its thread. A file whose patch is absent (too large, binary) maps to `null` = permissive, degrading to the old file-granularity behavior rather than refusing to anchor anything. This is why the context comes from `gh api .../pulls/N/files --paginate --slurp` and **not** `gh pr view --json files`: the latter omits `patch` entirely, and without patches per-line validation is impossible. Severity is **inferred** from `verdict` (`CONFIRMED` → high, else medium) because `ReportFindings` carries no severity field — the review body says so rather than presenting it as measured. `event` stays `COMMENT`: a bot `REQUEST_CHANGES` would block the merge behind a bot dismissal, and approvals/blocks stay human. Verified live on PR #869 — **one** review, `bodylen=838`, the inline comment carrying `pull_request_review_id` of that same review (3 findings → 1 inline + 2 body). No hook fires it: a `PostToolUse:ReportFindings` hook was considered and rejected — the payload carries no PR number (only `cwd`, and review checkouts are detached worktrees where `gh pr view` resolves nothing), it fires **twice** when `--fix` re-reports with outcomes, and **zero** times at low effort. Invocation stays manual.
- `tools/plan_review_dispatch.ts` + `plan_review_dispatch_lib.ts` — plan/spec document review dispatch (N agents × M domains, bounded 21-worker pool)
- `tools/iac_review.ts` (CLI) + `iac_review_lib.ts` (orchestrator) — **multi-agent IaC reviewer** backing `/stark-terraform-review` + `/stark-terragrunt-review`. Resolves a configurable agent list (CLI `--agents` > config `iac_review.agents` > `["codex"]`), collects in-scope `.tf`/`.hcl` (path or `--changed`), runs read-only host scanners as evidence, then dispatches **every agent in parallel as its own headless subagent** with the canonical rubric (`global/prompts/iac-review/{terraform,terragrunt}.md`) + line-numbered context. Parses each agent's JSON findings, dedups across agents (populates `cross_validated_by`), applies `--min-severity`, renders markdown (or `--json`), optionally posts to a PR via `github_app_lib::prReview` (authored by the first agent's App). Reuses the `copilot_dispatch.ts` dispatch primitives (`run`/`buildAgentEnv`/gemini-home+Vertex/API-key fallback/output parsers). Read-only (codex `-s read-only`, gemini plan mode); never mutates the target. Config: `iac_review` section in `stark_config_lib.ts` (`DEFAULT_IAC_REVIEW`).
- `tools/refactor_planner.ts` (CLI) + `refactor_planner_lib.ts` (orchestrator) — multi-agent **repository refactor-planning** dispatcher backing `/stark-refactor-plan`. Modes: `dry-run` (deterministic inventory + planned jobs, no LLM), `run` (10 focused subagents → `REFACTOR_PLAN.md` + `REFACTOR_BACKLOG.json`), `validate` (gate an existing backlog: schema + enum + unique/sequential ids + `depends_on` DAG + path-existence). Splits analysis into per-agent **context packs** (size-capped) instead of one whole-repo context. Supporting modules: `refactor_planner_discovery.ts` (deterministic host scan → `RepoInventory`: tree, languages, commands, import graph, cycles, TODOs, god-modules), `refactor_planner_context.ts` (per-agent packs + cycle detection), `refactor_planner_provider.ts` (`AgentProvider` interface + claude/codex/`noop` providers — provider/model from `--provider`/`--model`/`REFACTOR_PLANNER_*` env, never hardcoded; wraps `copilot_dispatch.ts` primitives), `refactor_planner_synth.ts` (host-owned conflict resolution + deterministic `PlanModel` assembly — tests-before-moves-before-deletes DAG), `refactor_planner_artifacts.ts` (renders the 14-section plan + builds/writes the backlog; planning-only writer), `refactor_planner_schemas.ts` (types, enums, runtime validators, the backlog gate). Prompts: `global/prompts/refactor-planner/*.md` (10 subagents). `noop` provider runs the whole pipeline with zero LLM calls (valid empty artifacts) for tests/CI. ### Agent utilities
- `tools/claude_utils_lib.ts` — Claude CLI dispatch helpers (clean env via `runtime_env_lib`, headless command builder, model pinning)
- `tools/codex_utils_lib.ts` — Codex CLI dispatch helpers (JSONL parsing, reasoning-effort config)
- `tools/gemini_utils_lib.ts` — Gemini CLI dispatch helpers (isolated `GEMINI_CLI_HOME`, Vertex-AI env, API-key fallback, JSON output parsing)
- `tools/agent_disabled_error.ts` — shared `AgentDisabledError` raised when an agent is config-disabled
- `tools/agent_claude.ts` — the claude reviewer agent. **Supports CLI-enforced structured output:** set `BuildContext.jsonSchema` and `buildCommand` emits `--json-schema <inline JSON>`, which forces a conforming reply and retries the model on mismatch. `parseOutput` consumes it directly — a schema forces ONE conforming value, not the JSONL one-finding-per-line stream, so it reads `structured_output` (accepting `{findings:[…]}` or a bare array) before falling back to the line scanner; without that branch a schema-forced reply parses to zero findings AND zero parse errors, which the dispatcher reports as a failed domain. Read it yourself with `extractStructuredOutput(rawStdout)` — the envelope carries a top-level **`structured_output` already parsed as an object** (`.result` stays a *string* of the same JSON, so reading `structured_output` skips a parse rather than duplicating one). **Pass RAW stdout, never `normalizeOutput(stdout)`** — normalizeOutput unwraps to `.result` and throws `structured_output` away, so that composition returns `null` on every run (pinned by a test). `null` means the field is genuinely absent (no schema, older CLI, non-envelope stdout) = fall back to tolerant text extraction (e.g. `refactor_planner_provider.ts::extractJsonObject`); an `is_error` envelope **throws** with the CLI's own message instead, so an exhausted account cannot masquerade as "no schema was passed". **Three gotchas, all verified against 2.1.220:** the flag takes **inline JSON only** — a file path fails with `--json-schema is not valid JSON`; it takes a JSON **object** only — `null`, `false`, a string and an array each exit 1 with `--json-schema must be a JSON object`, so `serializeJsonSchema` rejects non-objects up front with an attributed error; and it is Claude-only, so `BuildContext.jsonSchema` is inert for codex/gemini and safe to set unconditionally. Schemas are capped at **120 KiB** — the binding limit is Linux's per-argv-string `MAX_ARG_STRLEN` (32 × PAGE_SIZE = 128 KiB), *not* the looser macOS whole-vector ARG_MAX — so an oversized schema fails loudly here instead of as an opaque `E2BIG` from spawn on a CI runner.
- `tools/agent_env_lib.ts` — **single owner of the agent subprocess env allowlist** (`AGENT_ENV_ALLOWLIST`) plus the PATH backfill (`resolvedPath`). `agent_claude.ts` / `agent_codex.ts` / `agent_gemini.ts` / `optimize_skill_description.ts` all import it; they previously kept four identical copies and drifted. (`stark_review_lib.ts::DEFAULT_TEST_ENV_ALLOWLIST` is deliberately separate — the trusted test-command runner needs broader toolchain env than a reviewer subprocess.) **`USER` is load-bearing, not cosmetic** — without it the claude CLI cannot resolve its Keychain identity and degrades to an unauthenticated path, failing with `Not logged in · Please run /login` or `Credit balance is too low` depending on account state, with nothing pointing at the env as the cause. Reproduced deterministically against 2.1.220 (`env -i HOME=… PATH=… LANG=… TMPDIR=…` fails; adding `USER=…` succeeds, 3/3 both ways). `copilot_dispatch.ts` had already allowlisted `USER` in its own `DEFAULT_RUNTIME_ALLOWLIST`; that fix was never back-ported, which is the drift this constant ends. GH/Anthropic/OpenAI credential vars stay excluded so a reviewer subprocess cannot exfiltrate them — pinned by its own test, separate from the allowlist assertion.

- `tools/claude_auth_lib.ts` — **single source of truth for headless-claude model auth. ONE mode: `subscription`.** No `ANTHROPIC_API_KEY` is ever injected; the CLI rides the logged-in account's OAuth creds via `HOME`, billing the seat. The **metered-`api` mode is gone (2026-07-24)** — it was a standing footgun: a revoked `ANTHROPIC_AGENTS` key surfaced only as a generic `cli_error` after ~370s with no 401 anywhere in the subprocess output, and a *missing* one hard-failed dispatch even though the CLI authenticates fine on OAuth. `STARK_CLAUDE_AUTH` and `models.claude.auth` are **accepted-and-ignored** so old configs don't break; any value other than `subscription` warns to stderr. Codex/Gemini auth unaffected.

Imported by `gemini_utils_lib.ts`, `copilot_dispatch.ts`, `agent_gemini.ts` — the three former hardcode sites.

### Pipeline (end-to-end, in order)

- `/stark-author <intent|notes-path> [--tier skip|short|full] [--out PATH] [--no-advisory] [--ready]` — **Stage 1 (evidence-based rewrite): human-gated spec+plan authoring in ONE session.** Tier check (skip/short/full by uncertainty, not length) → time-boxed recon (~10–15 tool calls) → structured interview (fixed question order, EARS-shaped behavior contract, voiced ambiguities capped at 3, five-part stopping rule) → one self-contained doc (`docs/specs/YYYY-MM-DD-<slug>-spec.md`: intent, IN/OUT boundary, non-derivable repo context, EARS criteria, task DAG sized in tens of human-minutes with machine-checkable done-whens, closing verification command, append-only Deviations; plus a NON-normative plain-English operator digest sidecar `docs/specs/YYYY-MM-DD-<slug>-spec.human.md` — **gate-shaped, not a prose summary**: one fixed section per gate checklist item, carrying the artifacts the tripwire-bearing items bite on (interfaces, verification command, unwanted-behaviour criteria, per-task done-whens) **verbatim in code spans**, under a *material-never-verdicts* rule that bans pre-supplying any item's answer (false-PASS shape, missing-OUT, weak done-when, cuttable task, risk reassurance); ≤60 lines Full / ≤20 Short, regenerated on every revision — spec wins on conflict) → at most ONE zero-shared-context advisory subagent pass (findings go to the human once, never a loop) → human gate (8 value-stating checklist items, <60 min/<400 lines, rubber-stamp tripwires) → pin (`accepted-base` commit hash) → draft PR (`spec/<slug>`, stark-claude) → fresh-session handoff contract. **No LLM-reviews-LLM loop anywhere; no growth breakers needed because there is no loop to contain.** For new work it replaces write-spec → review-spec → red-team-spec → spec-to-plan → review-plan. Evidence: `skill/stark-author/references/stage1-dossier.md` (61 claims, 3-vote adversarial verification). Skill `skill/stark-author/SKILL.md` — pure protocol, zero new TS machinery. **Phase 3 carries a wiring-seam checklist (added 2026-07-30)** — the highest-value fix from the `hibob-profiles-cache` run, where **5 of 8 tasks** had to touch a file outside their declared set, every one the same category: a seam without which the task's work is inert. Before a file set is final, scan four classes: **registration/dispatch** (migration step lists, capability registries, route tables — a migration `.sql` is inert data until the step list runs it), **generated artifacts pinned by tests** (schemas/catalogs/generated docs that adding a struct field makes stale by construction), **call sites** (a new helper with zero callers is dead code behind a green gate — the T6 failure: an audit helper would have shipped with the behavior clause holding nowhere, and the gate would have passed), and **doc/description generators** (where the emitted text actually lives). The closing authoring test: *"if this task's diff were applied and nothing else, would the behavior criterion actually hold at runtime?"* A done-when can pass while the answer is no — that is the vacuous-green the whole two-stage design exists to prevent.
- `/stark-build <spec-path> [--dry-run] [--no-advisory] [--no-fix] [--stay-draft] [--max-turns N] [--model ID]` — **Stage 2 (evidence-based rebuild): autonomous implementation from an accepted `/stark-author` spec** (the two-stage architecture replacing the loop pipeline below). The interactive session is the RUNNER: it dispatches one fresh headless `claude -p` session per spec task, **gated by checks the agent cannot edit** — a PreToolUse path-deny hook write-protects the spec + gated existing tests + harness scripts (`skill/stark-build/references/hooks/protect-paths.sh`), and a Stop-hook gate blocks turn-end while the task's done-when check is red, flipping to **abort-with-deviation at 7 consecutive blocks** so Claude Code's 8-block override never lands a silent green (`references/hooks/stop-gate.sh`). Abort is a first-class success (measured 54%→9% cheating cut); anti-cheat prompting is never the gate. Sequential single writer; worktree at the spec's `accepted-base`; branch `build/<slug>` + immediate draft PR via `tools/copilot_land.ts` (create-or-adopt, never force); one commit per green task; crash/timeout = ONE resume from PROGRESS.md + commits, never from zero. The runner verifies every task deterministically (re-runs the check itself, diff-vs-protected-list tamper check, diff-vs-declared-file-set scope check). The spec's closing verification command is a **held-out e2e gate** (task-green/e2e-red divergence = the gaming/mis-decomposition signal; PR stays draft). ONE cross-vendor advisory review (codex, read-only, full diff + spec) posts severity-tagged findings to the PR (pinned `SEVERITY: critical|high|medium|low` ladder so the filter is machine-readable), followed by **Phase 4b — exactly ONE fix round over the medium+ findings** (`--no-fix` opts out): a single fresh headless session under the same hook harness, e2e as its Stop-gate check, told to fix only what the findings name and to *reject* a wrong finding with a logged reason rather than fake it. The runner then re-runs every task check + e2e itself and reverts the fix commit on any regression — **the advisory reviewer is never re-run, there is no round 2, and `low` + anything still open dies at the human**. A rejection is a claim, not a resolution: any medium+ left open keeps the PR draft. Fix-round yield (selected/fixed/rejected/regressed) is the kill-switch metric. State + evidence under `~/.claude/code-review/history/build/<slug>/<run-id>/`, never the repo. Protocol skill + two POSIX hook scripts. Evidence: `skill/stark-build/references/stage2-dossier.md` (9 RQs, measured anti-cheat data). Skill `skill/stark-build/SKILL.md`. **Six harness defects fixed 2026-07-30** from the `hibob-profiles-cache` run: (1) **every dispatched subprocess closes stdin** (`</dev/null`) — both `claude -p` and `codex exec` read stdin *in addition to* the prompt arg, and an orchestrated shell's stdin is a pipe that never EOFs, so `codex exec` hung 5h14m emitting 39 bytes; the rule covers `stop-gate.sh`'s own check invocation too (a Stop hook's stdin is the payload pipe), while `protect-paths.sh` is the deliberate exception since it must read the payload; (2) the Phase-2 prompt directed evidence into `$STATE/tasks/<id>/`, which `protected.list` blocks — evidence now goes to `$STATE/evidence/<id>.log`; (3) **long gates run backgrounded and stop via task-stop, never a foreground timeout**, which leaks the child tree so each retry competes with its predecessors (four concurrent check.sh, oldest 52min) and reads as external contention; (4) `bash check.sh` proved unreliable where its own content was not, so the runner may run the done-when **verbatim and unmodified** when the wrapper won't return (root cause undiagnosed — determinism is preserved because the command is identical and still runner-run) — plus **macOS has no `timeout(1)`**, so a `timeout`-wrapped sweep reports every gate as a false red in 0s via exit 127; (5) broad kill patterns (`pkill -f "go test"`) match command-line text, not ownership — they killed the runner's *own* in-flight gate (manufacturing a misread `rc=143`) and a *different* concurrent run's task; (6) `prepare-branch` now takes `--require-base` (see its entry above) and Phase 1 asserts the pin independently. **Nine further defects fixed the same day from an xhigh review of that fix** — the two that could still land a false green: `protected.list` directory entries written **with a trailing slash** built the glob `<dir>//*`, which matches nothing, so the Edit/Write deny branch passed every file under it and a task session could rewrite its own `check.sh` (`protect-paths.sh` now normalizes trailing slashes itself — the runner is an LLM filling a template, so the hook cannot depend on the prose); and the wrapper-flake fallback said to re-run the done-when "verbatim from the spec", which drops the wrapper's `set -euo pipefail; cd <wt>` envelope and so greens a task against the **main checkout** (it now runs the check file's whole content). Also: the runner's own gate invocations keep the `bash` prefix (`check.sh` has no shebang and is never `chmod +x` — direct execution is a 126 false red on every task) and close stdin (the runner's stdin never EOFs, which is the likeliest explanation for the undiagnosed wrapper flake); the `perl -e 'alarm N; exec'` timeout substitute was **removed** — `alarm` signals only the exec'd shell, orphaning exactly the `go test` children the paragraph above it bans, so a hard bound must kill the process **group**; and `pgrep -af` was replaced with `pgrep -lf`, since on macOS `-a` means *include ancestors* (it prints bare PIDs and widens the set to the orchestrating session, so killing that list ends the run). For implementation from an accepted spec it replaces copilot's review loop, plan-to-tasks, and phase-execute.
- `/stark-copilot <plan-or-prompt> [--lead AGENT] [--wing AGENT] [--plan-slug SLUG] [--no-goal] [--sequential] [--parallel] [--ready]` — autonomous implementation with paired lead/wing subagents (default lead `claude`, wing `codex`); lead implements in worktree, wing reviews diff, **one fix round by default** (`--max-rounds` 1; unresolved goes to the human, not another loop). When lead is `claude`, the implement prompt is `/goal`-prefixed by default (`--no-goal` to disable) — **round 1 only; fix rounds never goal-loop**. Tests auto-detect + host-run per round; **approve over red tests does not land** (`approved_but_tests_red`). §2b passes `--diff-out` so the final diff rides disk (`final_diff_path`), never model context. **Plans its own execution first (§1.2.7 + §1.4):** builds a **task-level** dependency DAG (issue `## Dependencies` / phase `depends_on` / plan-text edges; ambiguous ⇒ dependent, fail-closed; open human-led dependency ⇒ dependents skipped, not run), **chain-collapses** linear task runs into single steps (a fully-linear phase = one step = zero overhead regression) and levels the steps into waves with phase barriers, then fans each multi-step wave out concurrently via a Workflow (one dispatcher loop per step, own worktree, per-step result files — diffs never round-trip through model output) — parallelism is on by default; `--sequential` disables it, `--parallel` force-collapses all steps into one wave. Wave apply is atomic (reset on failed 3-way, clean-tree precondition, seeded re-dispatch on cross-step conflicts); dispatcher `final_diff` is the `--binary --full-index` rendering while the wing reviews the textual diff. Issue-driven mode when task issues exist (formerly created by the retired plan-to-tasks stage). **Lands an impl PR (§1.7/§2.6, via `tools/copilot_land.ts`)** — historically copilot only committed steps locally and never opened a PR. Before the first step commits, §1.7 adopts-or-creates a deterministic `copilot/<slug>` branch (`copilot_land.ts branch-name` + `prepare-branch`, ff-only, never force) so every step's commit lands there; after all waves + end-of-run verification, §2.6 pushes (never `--force`) and adopts-or-opens the PR (`copilot_land.ts land`, draft by default, `--ready`/`--no-draft` opts out, authored by the lead's GitHub App). §4b posts the run summary to that same resolved PR — it no longer runs its own competing `gh pr view` detection. Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the last line of output, carrying `plan_slug` + the complete `prs` array (newly opened plus adopted). **Playground-scope guard:** the copilot `implement`/`review` prompts (`global/prompts/copilot/{claude,codex,gemini}/`) carry the scope discipline — the lead doesn't build production ceremony (auth/HA/retries/audit/migration) the step never asked for, and the wing treats over-engineering as an `over-engineering` finding to cut instead of demanding more machinery.
- `/stark-gh:pr-merge [--pr N] [...]` — rebase + draft squash prose & CHANGELOG entry via Codex + force-push + **mark a draft PR ready-for-review** (fires the target CI) + squash-merge once CI is green. A repo with **no root CHANGELOG.md skips the changelog step** (edit/commit/restore) instead of dying with exit 15; a CHANGELOG that exists but lacks `## [Unreleased]` is still the hard error — malformed, not absent. **The squash subject inherits the PR title's ticket prefix** (STARK-229): a lower-case `type(TICKET-<n>):` title (`feat(STARK-193):`) makes that prefix mandatory on the drafted subject — enforced as a token in `lib/draft_schema.ts` (one space + non-empty summary, no repeated prefix, an added `!` allowed, and the ≤72-char cap measured *after* the prefix so the two constraints can't collide inside the 2-attempt budget), retried once, then **abort with `DRAFT_INVALID`** rather than landing a prefix-less commit on main. The ticket key must look like one (`STARK-229`, `EI-1234`) — an ordinary scope like `docs(adr-0007):`/`feat(gpt-5):`, or a capitalized type, mints **no** requirement, so repos without a ticket convention are never merge-blocked
- **`/stark-gh:pr-merge` reads per-repo defaults from the same `.stark-gh.json`** (STARK-293) — a `merge` block supplying `allowNoRequiredChecks`, `allowSecretToLlm`, `allowSecretCommit`, `noWatch`, `watchTimeoutHours` (**≤168h on BOTH the config and the `--watch-timeout` flag** — a watcher's timeout is its only guaranteed exit and it holds a lock that blocks every later merge of that PR). Motivation is REPETITION, not data loss: since `efdffed` a vacuous rollup goes terminal after the 300s grace naming `--allow-no-required-checks` as the remedy, so a repo with no PR CI just makes the operator retype it forever for a fact that never changes. **Read from the repo's DEFAULT branch, after Step 7's fetch.** Three wrong sources were tried first and each is a real hole: the working tree lets a branch ship the waivers that clear its own diff; `pr.baseRefName` lets a STACKED PR do the same by targeting a branch its author just pushed (the fork gate never fires — same repo); and reading before the fetch both hard-fails on a base ref never fetched locally and silently applies stale trunk policy. A PR based on anything but the default branch is told the file was skipped. **Precedence: config supplies defaults, the CLI wins** — every key only turns something ON, so it is an OR with no inverse, and **`--ignore-repo-config`** is the single-run escape (also the only way past a committed-and-broken file). **`pr-open` validates the block but WARNS rather than dying** — it has no `--ignore-repo-config`, so failing there would let one bad commit block opening a PR from every branch. Every applied setting prints as `in effect — <flag>: <file>` (`noWatch` included — it skips the CI-green wait), and gate waivers are written to the override audit with `source: "cli" | "repo-config"` so a standing repo setting is never mistaken for a decision about that merge. **Near-miss keys are fatal at BOTH levels** (`"Merge"`, and `allowNoRequiredCheck` inside the block) — a silently inert config is the exact failure the feature removes. `fileAtRef` establishes absence with `ls-tree`, never by matching git's localized stderr. Owner: `lib/merge_config.ts`; the file's top-level key set is `ticket.ts::KNOWN_TOP_LEVEL_KEYS`, shared by both loaders.
- **`/stark-gh:pr-open` gates the PR TITLE on a ticket, per-repo opt-in** (STARK-247) — the front half of the rule above, since a title with no ticket gave the merge side nothing to inherit. A repo declares the convention in **`.stark-gh.json`** at its root (`{"requireTicketScope": true, "ticketKey": "STARK"}` — **`ticketKey` is mandatory when enforcing**, since a keyless scan fabricates tickets from version tokens like `AWS-2`); preflight resolves the ticket from the **branch name** (case-insensitive against `ticketKey`, underscore-separated, so `stark-247`/`worktree-STARK-229`/`feature_STARK-247` all resolve) and pins it into the drafter's prompt + output validation. An explicit `--title` is **validated, never rewritten — on create AND on an existing-PR title edit** (pr-open writes `--title` onto an existing PR, so exempting that path bypassed the gate): missing / mismatched / wrong-case ticket exits **33**, as does a new PR with no resolvable branch ticket; an existing PR whose title is untouched is not gated. **Default off** (stark-gh runs on Evinced/OSS repos where `STARK-` is meaningless), but a **present-but-broken** `.stark-gh.json` — bad JSON, wrong type, or enabling without `ticketKey` — is a **fatal exit-33 error, not a silent revert to off** (a gate you opted into fails closed). There is still **no CI title check** — `lib/ticket.ts` is the only enforcement that runs
- `/stark-gh:cleanup [--pr N] [--dry-run] [--keep-branch NAME] [--no-rebase] [--no-watcher-cleanup] [--no-config] [--no-gc] [--drop-stale-stashes] [--force] [--json]` — sweep merged/stale branches (local + remote), prune tracking refs, remove worktree leftovers (including detached-HEAD `review-*-prN-*` worktrees for done PRs), clean merged-PR watcher state, surface stale stashes, `git gc` loose objects, and rebase current branch onto upstream so history stays linear. `--pr N` narrows to one PR's head ref + watcher state.

## Conventions

- **Docs live with the code** under `docs/`, folder per type — `adr/` (`NNNN-<topic>.md`, immutable: supersede, don't edit), `specs/` (`YYYY-MM-DD-<topic>-spec.md`), `retros/` (`YYYY-MM-DD-<topic>-retro.md`). **This is the layout `/stark-init-docs` scaffolds into a target repo, and `tools/doc_convention.test.ts` guards that scaffolding — it is not a layout this repo keeps.** stark-skills itself carries no `docs/` tree: every skill is documented by its own `SKILL.md` and its `--help`, and the generated docs layer was deleted once its generator was. **There is never a `docs/plans/`** — since `/stark-author` (2026-08-01) the spec carries the plan (task DAG, per-task done-whens, closing verification command), which `/stark-build` consumes. Tier by blast radius: trivial → PR only · feature → spec · architectural → ADR + spec.
- Prompts are per-agent: each LLM gets its own version of each domain
- Domain IDs are slugs derived from filenames: `01-architecture.md` → `architecture`
- Config uses JSON, prompts use markdown
- Agent preambles in `agent.md`, domain prompts in `NN-domain.md`
- **Every skill honors `--help`.** Each `skill/*/SKILL.md` opens with a `## Help` block right after its frontmatter that points at the shared `standards/help.md` protocol: a standalone `--help`/`-h`/`help` token in `$ARGUMENTS` prints the skill's purpose + usage + `## Arguments` and stops (no preflight, no phases, side-effect-free). The `skill_smoke_test.test.ts` guard asserts every skill references `standards/help.md`.
