# CLAUDE.md — stark-skills

## What This Is

Multi-agent PR code review system. Claude, Codex, and Gemini are all enabled (Gemini → `gemini-3.1-pro-preview`, default auth **oauth** — the logged-in Google account's Code Assist seat; `vertex` and `api-key` modes remain via `models.gemini.auth` / `STARK_GEMINI_AUTH`, see `tools/gemini_auth_lib.ts`). The Vertex **project/location are resolved at runtime** by `tools/vertex_config_lib.ts` (env > config > `GOOGLE_CLOUD_PROJECT` > local `gcloud`) — **never hardcoded/committed in source**; in oauth mode the resolved project doubles as the Code Assist licensing project. Note: `-latest` aliases like `gemini-pro-latest` only resolve via the Generative-Language API-key fallback, **not** Vertex. Hierarchical config (global → org → repo). Self-improving prompts via review history analysis.

## Operating Principles

This is a **personal playground**, not production. No customers depend on it; the only user is the author.

- **No rollout ceremony.** Skip soaking, gating, smoking, canary, and gradual-rollout patterns. Merge straight to main once the PR is green.
- **Branch + PR for everything — nothing lost.** Every change lands on a branch and merges via PR; never commit or push to `main` directly. "Ship straight to main" means merge once green, not bypass the PR. This repo **is** the review system — so every review's findings get posted on the PR as comments (inline where anchored, summary otherwise; `multi_review.ts` already does the GitHub posting). Don't drop, downgrade, or summarize findings away, and don't merge with open findings unaddressed — fix them, or reply on the thread saying why not.
- **Draft PRs by default — test locally, un-draft to merge.** Every PR-opening path opens a **draft** so WIP stays out of draft-guarded CI while you verify locally. The single owner of the default is the `pr create` CLI (`tools/github_app.ts` → `github_app_lib.ts::prCreate`, `draft ?? true`); the stark-gh `pr-open` tool, the review / red-team / spec-to-plan / phase-execute skills, and the automation-fleet prompts all inherit or set it. Opt out per-run with `--ready` (alias `--no-draft`). **You cannot merge a draft**, so the merge paths un-draft first: `/stark-gh:pr-merge` (and `github_app.ts pr ready` / `gh pr ready`) mark the PR ready-for-review — which fires the target CI via the `ready_for_review` event — then wait for green, then squash-merge. For "no CI on WIP" to actually hold, each target repo's `pull_request` workflows need the **skip-draft guard** (`if: github.event.pull_request.draft == false` + `ready_for_review` in `types`) — pattern + `== false` vs `!= true` guidance in `standards/workflows/skip-draft-guard.md`. Exempt: push-triggered publishers like `marketplace-sync` that must run CI + auto-merge (they open ready).
- **Language preference:** Go for backend, TypeScript for scripts. **Avoid Python at all costs** — the repo's tooling is now TypeScript-only (`tools/`); the former Python orchestrators + dispatch infra under `scripts/` were migrated out. Do not introduce new Python.
- **Test live.** Local-only verification is not enough. If a flow touches GCP, exercise the real GCP surface.
- **Always update documentation.** Any change that affects behavior, structure, commands, env vars, or operations must update the relevant docs (this file and `AGENTS.md` included) in the same change.

## Distribution

This repo is the **source of truth** for the skills + tools. Distribution is **marketplace-only** — the former `install.sh` symlink installer was removed (2026-07-07); there is no local symlink install step.

- **bifrost** (the marketplace; formerly `stark-marketplace`, renamed 2026-07-11) — the `bifrost` repo packages these skills as self-contained Claude Code plugins (`/plugin marketplace add 21StarkCom/bifrost`, then `/plugin install <bundle>@bifrost`). Its `catalog/` is **generated from this repo** by `stark sync`, and its engine vendors `tools/`+`global/` (config + prompts) into each plugin so an install needs no symlinks and no setup step. `/plugin update <bundle>@bifrost` pulls the latest published version. CI auto-publishes: `.github/workflows/marketplace-sync.yml` regenerates the marketplace and opens a PR on every push to `main` touching a vendored asset root — `skill/`, `tools/`, `global/`, `scripts/`, `standards/`, or `plugins/stark-gh/`.
- **Local dev is no longer live.** Editing a file in this repo does not take effect until the change is published (merge to `main` → `marketplace-sync` PR → merge) and the plugin is reinstalled/updated (`/plugin update …`). To test an in-progress edit against a real install, run `stark sync` in the marketplace repo and `/plugin update` locally.
- **Assets plugins don't cover** (user `~/.claude/settings.json`, statusline, output-styles, `org/evinced` overrides, mutable-state dirs, git hooks) are now managed by hand — the installer no longer provisions them.

**The plugin-resolution seam:** `tools/asset_root_lib.ts` — `assetRoot()` resolves immutable assets (tools/prompts/config) from `${CLAUDE_PLUGIN_ROOT}` when running inside an installed plugin, falling back to `~/.claude/code-review` for direct (non-plugin) invocations such as automation-fleet crons; `stateRoot()` always stays under `$HOME`. Skills mirror this with `${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/code-review}`. **Never hardcode `~/.claude/code-review/{tools,prompts,scripts,standards}` in a skill or tool** — route immutable-asset reads through `asset_root_lib`/the dual-fallback so plugin installs keep working.

- `tools/red_team_lib.ts` — red-team dispatcher core. Persona/prompt resolution from `global/prompts/red-team/`, codex dispatch with sandbox (env scrubbing + isolated HOME), per-finding validation, sidecar markdown rendering, pre-dispatch sensitive-data gate, redaction sanitizer, data-classification gate (YAML-frontmatter driven; see `docs/specs/red-team-classification-contract-2026-05-16.md`), `--replay-transcript` support. **Pre-dispatch gate scans untrusted input only** — `preDispatchSensitiveGate` runs over `untrustedGatePayload([artifact, sourceSpec, …])` (the document under review), **never** the assembled prompt: the preamble legitimately quotes attacker phrases like `"ignore previous instructions"` as examples, and scanning them self-tripped `injection_ignore_prior` on **every** run (a #627 regression that 100%-blocked the gate once published; the pre-published marketplace copies masked it). ### Pipeline (end-to-end, in order)

- `/stark-author <intent|notes-path> [--tier skip|short|full] [--out PATH] [--no-advisory] [--ready]` — **Stage 1 (evidence-based rewrite): human-gated spec+plan authoring in ONE session.** Tier check (skip/short/full by uncertainty, not length) → time-boxed recon (~10–15 tool calls) → structured interview (fixed question order, EARS-shaped behavior contract, voiced ambiguities capped at 3, five-part stopping rule) → one self-contained doc (`docs/specs/YYYY-MM-DD-<slug>-spec.md`: intent, IN/OUT boundary, non-derivable repo context, EARS criteria, task DAG sized in tens of human-minutes with machine-checkable done-whens, closing verification command, append-only Deviations; plus a NON-normative plain-English operator digest sidecar `docs/specs/YYYY-MM-DD-<slug>-spec.human.md`, regenerated on every revision — spec wins on conflict) → at most ONE zero-shared-context advisory subagent pass (findings go to the human once, never a loop) → human gate (8 value-stating checklist items, <60 min/<400 lines, rubber-stamp tripwires) → pin (`accepted-base` commit hash) → draft PR (`spec/<slug>`, stark-claude) → fresh-session handoff contract. **No LLM-reviews-LLM loop anywhere; no growth breakers needed because there is no loop to contain.** For new work it replaces write-spec → review-spec → red-team-spec → spec-to-plan → review-plan. Evidence: `skill/stark-author/references/stage1-dossier.md` (61 claims, 3-vote adversarial verification). Skill `skill/stark-author/SKILL.md` — pure protocol, zero new TS machinery.
- `/stark-build <spec-path> [--dry-run] [--no-advisory] [--stay-draft] [--max-turns N] [--model ID]` — **Stage 2 (evidence-based rebuild): autonomous implementation from an accepted `/stark-author` spec** (the two-stage architecture replacing the loop pipeline below). The interactive session is the RUNNER: it dispatches one fresh headless `claude -p` session per spec task, **gated by checks the agent cannot edit** — a PreToolUse path-deny hook write-protects the spec + gated existing tests + harness scripts (`skill/stark-build/references/hooks/protect-paths.sh`), and a Stop-hook gate blocks turn-end while the task's done-when check is red, flipping to **abort-with-deviation at 7 consecutive blocks** so Claude Code's 8-block override never lands a silent green (`references/hooks/stop-gate.sh`). Abort is a first-class success (measured 54%→9% cheating cut); anti-cheat prompting is never the gate. Sequential single writer; worktree at the spec's `accepted-base`; branch `build/<slug>` + immediate draft PR via `tools/copilot_land.ts` (create-or-adopt, never force); one commit per green task; crash/timeout = ONE resume from PROGRESS.md + commits, never from zero. The runner verifies every task deterministically (re-runs the check itself, diff-vs-protected-list tamper check, diff-vs-declared-file-set scope check). The spec's closing verification command is a **held-out e2e gate** (task-green/e2e-red divergence = the gaming/mis-decomposition signal; PR stays draft). ONE cross-vendor advisory review (codex, read-only, full diff + spec) posts severity-tagged findings to the PR — **findings die at the human; no fix loop anywhere**. State + evidence under `~/.claude/code-review/history/build/<slug>/<run-id>/`, never the repo. Zero new TS — protocol skill + two POSIX hook scripts. Evidence: `skill/stark-build/references/stage2-dossier.md` (9 RQs, measured anti-cheat data). Skill `skill/stark-build/SKILL.md`. For implementation from an accepted spec it replaces copilot's review loop, plan-to-tasks, and phase-execute.
- `/stark-forge <intent|spec-path|plan-path> [--red-team] [--from STAGE] [--until STAGE] [--resume] [--dry-run] [--json]` — **the conductor.** A thin orchestrator that chains the six pipeline stages below (8 with `--red-team`) in-session and owns a crash-resumable, merge-at-artifact-boundaries state machine — **glue, not logic**: it invokes each stage's slash command in-session and drives `tools/forge_state.ts`; it computes nothing itself (chain, merge points, per-stage command, base-sync routing all come from `forge_state.ts`). Each stage reports back on a single `STARK_STAGE_SUMMARY` line (`standards/stage-completion-line.md`, the pinned §4 completion channel — forge always invokes stages **without `--json`**, so the channel rides the human output path) that forge maps onto `record-output`. **Artifacts merge at their last touching stage** (spec after the last spec stage, plan after the last plan stage, impl after copilot; plan-to-tasks never merges) via `/stark-gh:pr-merge`; **base sync** (`git switch <default-branch>` + `git pull --ff-only`) fires only for the three new-artifact stages (`spec-to-plan`, `plan-to-tasks`, `copilot` — routing owned by `forge_state_lib.ts::requiresBaseSync`), never for same-artifact continuation stages. Crash recovery: `--resume` reconciles a `running` stage via one atomic `crashed`-attempt primitive, then acts on a closed action enum (`reinvoke | advance | complete | merge_only | abandon`); plan-to-tasks reconciles by its `issue_numbers` marker and is crash-safe because the stage's plan-scoped issue dedup makes re-invocation idempotent. **Mode** = in-session by default (`PHASE0_MODE_VERDICT`); `STARK_FORGE_DRIVER=1` switches to **driver mode**, which prints operator command blocks (`forge_state.ts driver-block`) instead of executing. `--dry-run` prints the resolved chain + merge points + per-stage commands (§9 summary) with zero side effects. State lives under `stateRoot()/history/forge/<slug>/<run-id>/state.json` (mode 0600, per-slug `latest` pointer, `history_keep_runs` retention), never in the repo; runs are repository-bound (recorded `{host, owner, name}` + `default_branch`, resolved once at `init`). Skill `skill/stark-forge/SKILL.md`; state manager `tools/forge_state{,_lib}.ts`; config section `forge_pipeline`; spec `docs/specs/2026-07-19-stark-forge-spec.md`, plan `docs/plans/2026-07-19-stark-forge-plan.md`.
- `/stark-write-spec <path|"intent"> [--out PATH] [--lead claude|codex] [--wing claude|codex] [--lead-model ID] [--wing-model ID] [--max-rounds N] [--dry-run] [--ready] [--no-pr] [--json]` — **stage 0: contract-bounded spec authoring** (the missing authoring stage upstream of review). Turns intent (inline prompt, notes file, and/or decisions distilled from the conversation) into a spec that satisfies a **fixed Spec Contract** (`global/prompts/write-spec/contract.md`, 9 sections inverting the review-spec domains), then hands off to the still-mandatory `/stark-review-spec`. A thin skill (assembles the intent brief, one `AskUserQuestion` gap-fill round) over a headless lead/wing dispatcher mirroring `plan_dispatch.ts`: lead drafts/revises against the contract, wing returns **one closed-enum status per section (NOT free-form findings)** — the host drops any unknown section id and **recomputes `done` over the full 9-id set, never trusting the wing** (partial/lazy verdicts fail closed). **Cannot ratchet like review-spec by construction**, so it carries no growth breakers, coherence pass, or analytics grading. Bounded loop (`max_rounds` default 3, early-exits to a single verify pass on a clean first draft). Five terminal verdicts (`contract_satisfied | max_rounds_unsatisfied | lead_empty_draft | unchanged_revision | wing_unparseable`); every non-crash exit writes the spec + receipt. On `max_rounds_unsatisfied` the skill offers **answer-the-gaps / accept-with-gaps (unsatisfied items appended to Open Questions verbatim) / abort** via `AskUserQuestion` (headless auto-accepts). Findings land on a **draft PR** via create-or-adopt idempotent landing (`write-spec/<slug>`, commit-on-top for re-runs, never force-push); handoff line `next: /stark-review-spec <spec>` reuses the same branch/PR trail. Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the literal last line of **human-mode** stdout (`/stark-forge` always invokes this skill without `--json`, per spec §2) — the sole exception to Phase 11's "no JSON on stdout in human mode" rule; the existing `--json` `SkillSummary` contract (exactly one JSON object, nothing else) is unchanged. Delegates to `tools/write_spec.ts`; architectural rationale in `docs/adr/0023-spec-authoring-contract-bounded.md`.
- `/stark-review-spec <path> [--fable] [--lead-agent codex|claude] [--lead-model ID]` — lead/wing spec review: codex (gpt-5.6-sol, xhigh) reviews 9 domains in parallel (cap 3 concurrent), claude (opus-5 1m) wing applies JSON patches. Pass `--fable` (or `--lead-agent claude`) to run the **lead review on Fable 5** (`claude-fable-5`) — explicit opt-in; the wing/fixer stays opus-5 1m. Multi-round fix loop with per-round git commit (max 2 rounds by default, wing batch capped at `max_fixes_per_round`=12 top-severity patches); circuit breakers stop pathological loops early — non-convergence (findings not declining) hard-stops, growth alone only warns + sets `analytics.growth_ack_required` (operator ack via AskUserQuestion before Phase 5; growth AND non-convergence together hard-stop), a **round-spike tripwire** halts-for-ack the first round that grows the doc >1.5x while findings are not declining, and a fix round that grows the doc under an open scope condemnation is discarded before commit; an explicit V1 boundary in the doc ("What this is NOT" / "deferred to Phase 2") is **binding** — reviewers and the wing treat deferred concerns as out of scope; the dispatcher runs **in the background by default**; a net-reducing coherence pass (contradictions/repetitions/fluff/leftovers, `--no-coherence` to skip) runs before the final review-only round that captures unresolved; every run writes process analytics (health grade + `<doc>.review-analytics.md` sidecar). Tournament mode removed in the TS port. Delegates to `tools/stark_review_doc.ts`. Findings always land on a PR — **opens one (feature branch + push, authored by stark-claude) if none exists**; a spec under the retired `docs/superpowers/**` tree is relocated to `docs/specs/` on that branch first. **Every finding is posted as its own resolvable review thread, fixed, and resolved:** after dispatch, `tools/review_doc_findings.ts post` threads every finding onto the PR (auto-resolving the wing-fixed ones), then the skill fixes each still-open finding — **asking the operator via `AskUserQuestion` when a fix is ambiguous or has options** — commits + pushes, and resolves each thread with the fix; below-threshold findings are fixed too. Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the literal last line of output, carrying the Phase 6 convergence outcome and the adopted/opened PR number.
- `/stark-red-team-spec <path> [--source-spec PATH] [--model ID] [--dry-run] [--no-pr-comment] [--ready] [--fold]` — adversarial committee challenge of a spec doc (auto-opened PR is a **draft** by default; `--ready`/`--no-draft` opens it ready) (5 personas × 1 round, default `gpt-5.5-pro`); writes `<spec>.red-team.md` sidecar and always lands findings on a PR — **opens one (pushing the spec doc + sidecar) if none exists**, else edits in place; the PR + findings comment are authored by the GitHub App matching the run's agent (`claude*`→stark-claude, `gpt*`/`o*`→stark-codex, `gemini*`→stark-gemini; codex by default); challenge-only, no fix loop (opt-in `--fold` runs `/stark-red-team-fold` after a successful challenge). Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the literal last line of output, carrying the challenge status/PR and — when `--fold` opened/edited a PR — its number in `fold_prs` (recovered from the fold step's stderr-routed summary, since `--fold` never surfaces the fold PR number in the challenge's own JSON).
- `/stark-spec-to-plan <path>` — generate implementation plan from spec doc via paired lead/wing loop (default lead `claude`, wing `codex`); lead drafts, wing reviews and emits JSON verdict, fix-loop until approved. Cheaper and lower-variance than the prior 3-agent tournament. **Sole producer of `plan_path`/`plan_slug`** (spec §4 SSOT): writes the plan to `docs/plans/YYYY-MM-DD-<slug>-plan.md` (the dispatcher's `derivePlanTarget`, slug from the SPEC path) and reports both plus the plan PR number as the terminal `STARK_STAGE_SUMMARY` line (`standards/stage-completion-line.md`) — downstream stages (`plan-to-tasks`, `copilot`) consume the recorded slug, never re-derive it. On approval the plan + per-round review summary **always land on a PR** — reuses an existing one, else **opens one** (branch + push, authored by the lead's GitHub App) — unless `--dry-run`. The revise step's self-review adds a **scope-proportionality scan** that cuts ceremony the spec never asked for.

Implement step is a goal-driven `claude -p "/goal …"` loop by default (`--no-goal` reverts to a bounded subagent). `--parallel` fans independent tasks (no `depends_on`) out via a Workflow, each in its own worktree; dependent tasks stay sequential.
- `/stark-copilot <plan-or-prompt> [--lead AGENT] [--wing AGENT] [--plan-slug SLUG] [--no-goal] [--sequential] [--parallel] [--ready]` — autonomous implementation with paired lead/wing subagents (default lead `claude`, wing `codex`); lead implements in worktree, wing reviews diff, fix-loop until approved. When lead is `claude`, the implement prompt is `/goal`-prefixed by default (`--no-goal` to disable). **Plans its own execution first (§1.2.7 + §1.4):** builds a **task-level** dependency DAG (issue `## Dependencies` / phase `depends_on` / plan-text edges; ambiguous ⇒ dependent, fail-closed; open human-led dependency ⇒ dependents skipped, not run), **chain-collapses** linear task runs into single steps (a fully-linear phase = one step = zero overhead regression) and levels the steps into waves with phase barriers, then fans each multi-step wave out concurrently via a Workflow (one dispatcher loop per step, own worktree, per-step result files — diffs never round-trip through model output) — parallelism is on by default; `--sequential` disables it, `--parallel` force-collapses all steps into one wave. Wave apply is atomic (reset on failed 3-way, clean-tree precondition, seeded re-dispatch on cross-step conflicts); dispatcher `final_diff` is the `--binary --full-index` rendering while the wing reviews the textual diff. Issue-driven mode when plan has been decomposed via `/stark-plan-to-tasks`. **Lands an impl PR (§1.7/§2.6, via `tools/copilot_land.ts`)** — historically copilot only committed steps locally and never opened a PR, so forge had no impl PR number to record or merge. Before the first step commits, §1.7 adopts-or-creates a deterministic `copilot/<slug>` branch (`copilot_land.ts branch-name` + `prepare-branch`, ff-only, never force) so every step's commit lands there; after all waves + end-of-run verification, §2.6 pushes (never `--force`) and adopts-or-opens the PR (`copilot_land.ts land`, draft by default, `--ready`/`--no-draft` opts out, authored by the lead's GitHub App). §4b posts the run summary to that same resolved PR — it no longer runs its own competing `gh pr view` detection. Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the last line of output, carrying `plan_slug` + the complete `prs` array (newly opened plus adopted). **Playground-scope guard:** the copilot `implement`/`review` prompts (`global/prompts/copilot/{claude,codex,gemini}/`) carry the scope discipline — the lead doesn't build production ceremony (auth/HA/retries/audit/migration) the step never asked for, and the wing treats over-engineering as an `over-engineering` finding to cut instead of demanding more machinery.
- `/stark-gh:pr-merge [--pr N] [...]` — rebase + draft squash prose & CHANGELOG entry via Codex + force-push + **mark a draft PR ready-for-review** (fires the target CI) + squash-merge once CI is green
- `/stark-gh:cleanup [--pr N] [--dry-run] [--keep-branch NAME] [--no-rebase] [--no-watcher-cleanup] [--no-config] [--no-gc] [--drop-stale-stashes] [--force] [--json]` — sweep merged/stale branches (local + remote), prune tracking refs, remove worktree leftovers (including detached-HEAD `review-*-prN-*` worktrees for done PRs), clean merged-PR watcher state, surface stale stashes, `git gc` loose objects, and rebase current branch onto upstream so history stays linear. `--pr N` narrows to one PR's head ref + watcher state.
- `/stark-review [PR_NUMBER]` — single-agent PR code review (1 LLM × triage-selected domains from 7, fast/cheap). The fix-loop test gate's `test_command` is **auto-detected** when unset: `stark_review_lib.ts::detectTestCommand()` reads the **trusted** `--config-root` checkout only (never the PR worktree — RCE guard) and recognizes Makefile `test:`/`npm test`/`go test`/`cargo test`/node:test `*.test.ts|js`/pytest-with-tests; resolution order is explicit `config.test_command` → detected → none (soft-skip via `allow_no_test_command`). Repos no longer pin a brittle `test_command` (the old `pytest scripts/` left from the Python era exited 5 every run). **Playground-scope guard:** the per-agent review preamble (`global/prompts/{claude,codex,gemini}/agent.md`, prepended to all 7 domains) carries the scope-proportionality block — a declared single-user/playground project is not held to auth/RBAC/HA/audit-log/migration/adversarial-input/exhaustive-test standards; real defects (crash/data-loss/wrong-output/broken-contract/scope-relevant-security) always stay in scope. Stops junk "add production hardening" comments on playground PRs.

## Conventions

- Prompts are per-agent: each LLM gets its own version of each domain
- Domain IDs are slugs derived from filenames: `01-architecture.md` → `architecture`
- Config uses JSON, prompts use markdown
- Agent preambles in `agent.md`, domain prompts in `NN-domain.md`
- **Every skill honors `--help`.** Each `skill/*/SKILL.md` opens with a `## Help` block right after its frontmatter that points at the shared `standards/help.md` protocol: a standalone `--help`/`-h`/`help` token in `$ARGUMENTS` prints the skill's purpose + usage + `## Arguments` and stops (no preflight, no phases, side-effect-free). The `skill_smoke_test.test.ts` guard asserts every skill references `standards/help.md`.
