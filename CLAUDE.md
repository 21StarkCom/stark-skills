# CLAUDE.md — stark-skills

## What This Is

The stark skills + tools fleet: a **two-stage development pipeline** (`/stark-author` human-gated spec+plan → `/stark-build` check-gated implementation — no LLM-reviews-LLM loops, per the 2026-07-25 autopsy and the 2026-07-26 demolition), a **single-agent PR code reviewer** (`/stark-review`, evidence-contract prompts), multi-agent IaC review, and the ops/session tier. Claude, Codex, and Gemini are all enabled (Gemini → `gemini-3.1-pro-preview`, default auth **oauth** — the logged-in Google account's Code Assist seat; `vertex` and `api-key` modes remain via `models.gemini.auth` / `STARK_GEMINI_AUTH`, see `tools/gemini_auth_lib.ts`). The Vertex **project/location are resolved at runtime** by `tools/vertex_config_lib.ts` (env > config > `GOOGLE_CLOUD_PROJECT` > local `gcloud`) — **never hardcoded/committed in source**; in oauth mode the resolved project doubles as the Code Assist licensing project. Note: `-latest` aliases like `gemini-pro-latest` only resolve via the Generative-Language API-key fallback, **not** Vertex. Hierarchical config (global → org → repo). Self-improving prompts via review history analysis.

## Operating Principles

This is a **personal playground**, not production. No customers depend on it; the only user is the author.

- **No rollout ceremony.** Skip soaking, gating, smoking, canary, and gradual-rollout patterns. Merge straight to main once the PR is green.
- **Branch + PR for everything — nothing lost.** Every change lands on a branch and merges via PR; never commit or push to `main` directly. "Ship straight to main" means merge once green, not bypass the PR. This repo **is** the review system — so every review's findings get posted on the PR as comments (inline where anchored, summary otherwise; `stark_review.ts` already does the GitHub posting). Don't drop, downgrade, or summarize findings away, and don't merge with open findings unaddressed — fix them, or reply on the thread saying why not.
- **Draft PRs by default — test locally, un-draft to merge.** Every PR-opening path opens a **draft** so WIP stays out of draft-guarded CI while you verify locally. The single owner of the default is the `pr create` CLI (`tools/github_app.ts` → `github_app_lib.ts::prCreate`, `draft ?? true`); the stark-gh `pr-open` tool, the review/author/build skills, and the automation-fleet prompts all inherit or set it. Opt out per-run with `--ready` (alias `--no-draft`). **You cannot merge a draft**, so the merge paths un-draft first: `/stark-gh:pr-merge` (and `github_app.ts pr ready` / `gh pr ready`) mark the PR ready-for-review — which fires the target CI via the `ready_for_review` event — then wait for green, then squash-merge. For "no CI on WIP" to actually hold, each target repo's `pull_request` workflows need the **skip-draft guard** (`if: github.event.pull_request.draft == false` + `ready_for_review` in `types`) — pattern + `== false` vs `!= true` guidance in `standards/workflows/skip-draft-guard.md`. Exempt: push-triggered publishers like `marketplace-sync` that must run CI + auto-merge (they open ready).
- **Language preference:** Go for backend, TypeScript for scripts. **Avoid Python at all costs** — the repo's tooling is now TypeScript-only (`tools/`); the former Python orchestrators + dispatch infra under `scripts/` were migrated out. Do not introduce new Python.
- **Test live.** Local-only verification is not enough. If a flow touches GCP, exercise the real GCP surface.
- **Always update documentation.** Any change that affects behavior, structure, commands, env vars, or operations must update the relevant docs (this file and `AGENTS.md` included) in the same change.

## Distribution

This repo is the **source of truth** for the skills + tools. Distribution is **marketplace-only** — the former `install.sh` symlink installer was removed (2026-07-07); there is no local symlink install step.

- **bifrost** (the marketplace; formerly `stark-marketplace`, renamed 2026-07-11) — the `bifrost` repo packages these skills as self-contained Claude Code plugins (`/plugin marketplace add 21StarkCom/bifrost`, then `/plugin install <bundle>@bifrost`). Its `catalog/` is **generated from this repo** by `stark sync`, and its engine vendors `tools/`+`global/` (config + prompts) into each plugin so an install needs no symlinks and no setup step. `/plugin update <bundle>@bifrost` pulls the latest published version. CI auto-publishes: `.github/workflows/marketplace-sync.yml` regenerates the marketplace and opens a PR on every push to `main` touching a vendored asset root — `skill/`, `tools/`, `global/`, `scripts/`, `standards/`, or `plugins/stark-gh/`.
- **Local dev is no longer live.** Editing a file in this repo does not take effect until the change is published (merge to `main` → `marketplace-sync` PR → merge) and the plugin is reinstalled/updated (`/plugin update …`). To test an in-progress edit against a real install, run `stark sync` in the marketplace repo and `/plugin update` locally.
- **Assets plugins don't cover** (user `~/.claude/settings.json`, statusline, output-styles, `org/evinced` overrides, mutable-state dirs, git hooks) are now managed by hand — the installer no longer provisions them.

**The plugin-resolution seam:** `tools/asset_root_lib.ts` — `assetRoot()` resolves immutable assets (tools/prompts/config) from `${CLAUDE_PLUGIN_ROOT}` when running inside an installed plugin, falling back to `~/.claude/code-review` for direct (non-plugin) invocations such as automation-fleet crons; `stateRoot()` always stays under `$HOME`. Skills mirror this with `${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/code-review}`. **Never hardcode `~/.claude/code-review/{tools,prompts,scripts,standards}` in a skill or tool** — route immutable-asset reads through `asset_root_lib`/the dual-fallback so plugin installs keep working.

### Pipeline (end-to-end, in order)

- `/stark-author <intent|notes-path> [--tier skip|short|full] [--out PATH] [--no-advisory] [--ready]` — **Stage 1 (evidence-based rewrite): human-gated spec+plan authoring in ONE session.** Tier check (skip/short/full by uncertainty, not length) → time-boxed recon (~10–15 tool calls) → structured interview (fixed question order, EARS-shaped behavior contract, voiced ambiguities capped at 3, five-part stopping rule) → one self-contained doc (`docs/specs/YYYY-MM-DD-<slug>-spec.md`: intent, IN/OUT boundary, non-derivable repo context, EARS criteria, task DAG sized in tens of human-minutes with machine-checkable done-whens, closing verification command, append-only Deviations; plus a NON-normative plain-English operator digest sidecar `docs/specs/YYYY-MM-DD-<slug>-spec.human.md`, regenerated on every revision — spec wins on conflict) → at most ONE zero-shared-context advisory subagent pass (findings go to the human once, never a loop) → human gate (8 value-stating checklist items, <60 min/<400 lines, rubber-stamp tripwires) → pin (`accepted-base` commit hash) → draft PR (`spec/<slug>`, stark-claude) → fresh-session handoff contract. **No LLM-reviews-LLM loop anywhere; no growth breakers needed because there is no loop to contain.** For new work it replaces write-spec → review-spec → red-team-spec → spec-to-plan → review-plan. Evidence: `skill/stark-author/references/stage1-dossier.md` (61 claims, 3-vote adversarial verification). Skill `skill/stark-author/SKILL.md` — pure protocol, zero new TS machinery.
- `/stark-build <spec-path> [--dry-run] [--no-advisory] [--no-fix] [--stay-draft] [--max-turns N] [--model ID]` — **Stage 2 (evidence-based rebuild): autonomous implementation from an accepted `/stark-author` spec** (the two-stage architecture replacing the loop pipeline below). The interactive session is the RUNNER: it dispatches one fresh headless `claude -p` session per spec task, **gated by checks the agent cannot edit** — a PreToolUse path-deny hook write-protects the spec + gated existing tests + harness scripts (`skill/stark-build/references/hooks/protect-paths.sh`), and a Stop-hook gate blocks turn-end while the task's done-when check is red, flipping to **abort-with-deviation at 7 consecutive blocks** so Claude Code's 8-block override never lands a silent green (`references/hooks/stop-gate.sh`). Abort is a first-class success (measured 54%→9% cheating cut); anti-cheat prompting is never the gate. Sequential single writer; worktree at the spec's `accepted-base`; branch `build/<slug>` + immediate draft PR via `tools/copilot_land.ts` (create-or-adopt, never force); one commit per green task; crash/timeout = ONE resume from PROGRESS.md + commits, never from zero. The runner verifies every task deterministically (re-runs the check itself, diff-vs-protected-list tamper check, diff-vs-declared-file-set scope check). The spec's closing verification command is a **held-out e2e gate** (task-green/e2e-red divergence = the gaming/mis-decomposition signal; PR stays draft). ONE cross-vendor advisory review (codex, read-only, full diff + spec) posts severity-tagged findings to the PR (pinned `SEVERITY: critical|high|medium|low` ladder so the filter is machine-readable), followed by **Phase 4b — exactly ONE fix round over the medium+ findings** (`--no-fix` opts out): a single fresh headless session under the same hook harness, e2e as its Stop-gate check, told to fix only what the findings name and to *reject* a wrong finding with a logged reason rather than fake it. The runner then re-runs every task check + e2e itself and reverts the fix commit on any regression — **the advisory reviewer is never re-run, there is no round 2, and `low` + anything still open dies at the human**. A rejection is a claim, not a resolution: any medium+ left open keeps the PR draft. Fix-round yield (selected/fixed/rejected/regressed) is the kill-switch metric. State + evidence under `~/.claude/code-review/history/build/<slug>/<run-id>/`, never the repo. Zero new TS — protocol skill + two POSIX hook scripts. Evidence: `skill/stark-build/references/stage2-dossier.md` (9 RQs, measured anti-cheat data). Skill `skill/stark-build/SKILL.md`. For implementation from an accepted spec it replaces copilot's review loop, plan-to-tasks, and phase-execute.
- `/stark-copilot <plan-or-prompt> [--lead AGENT] [--wing AGENT] [--plan-slug SLUG] [--no-goal] [--sequential] [--parallel] [--ready]` — autonomous implementation with paired lead/wing subagents (default lead `claude`, wing `codex`); lead implements in worktree, wing reviews diff, **one fix round by default** (`--max-rounds` 1; unresolved goes to the human, not another loop). When lead is `claude`, the implement prompt is `/goal`-prefixed by default (`--no-goal` to disable) — **round 1 only; fix rounds never goal-loop**. Tests auto-detect + host-run per round; **approve over red tests does not land** (`approved_but_tests_red`). §2b passes `--diff-out` so the final diff rides disk (`final_diff_path`), never model context. **Plans its own execution first (§1.2.7 + §1.4):** builds a **task-level** dependency DAG (issue `## Dependencies` / phase `depends_on` / plan-text edges; ambiguous ⇒ dependent, fail-closed; open human-led dependency ⇒ dependents skipped, not run), **chain-collapses** linear task runs into single steps (a fully-linear phase = one step = zero overhead regression) and levels the steps into waves with phase barriers, then fans each multi-step wave out concurrently via a Workflow (one dispatcher loop per step, own worktree, per-step result files — diffs never round-trip through model output) — parallelism is on by default; `--sequential` disables it, `--parallel` force-collapses all steps into one wave. Wave apply is atomic (reset on failed 3-way, clean-tree precondition, seeded re-dispatch on cross-step conflicts); dispatcher `final_diff` is the `--binary --full-index` rendering while the wing reviews the textual diff. Issue-driven mode when task issues exist (formerly created by the retired plan-to-tasks stage). **Lands an impl PR (§1.7/§2.6, via `tools/copilot_land.ts`)** — historically copilot only committed steps locally and never opened a PR. Before the first step commits, §1.7 adopts-or-creates a deterministic `copilot/<slug>` branch (`copilot_land.ts branch-name` + `prepare-branch`, ff-only, never force) so every step's commit lands there; after all waves + end-of-run verification, §2.6 pushes (never `--force`) and adopts-or-opens the PR (`copilot_land.ts land`, draft by default, `--ready`/`--no-draft` opts out, authored by the lead's GitHub App). §4b posts the run summary to that same resolved PR — it no longer runs its own competing `gh pr view` detection. Emits the pipeline's `STARK_STAGE_SUMMARY` completion line (`standards/stage-completion-line.md`) as the last line of output, carrying `plan_slug` + the complete `prs` array (newly opened plus adopted). **Playground-scope guard:** the copilot `implement`/`review` prompts (`global/prompts/copilot/{claude,codex,gemini}/`) carry the scope discipline — the lead doesn't build production ceremony (auth/HA/retries/audit/migration) the step never asked for, and the wing treats over-engineering as an `over-engineering` finding to cut instead of demanding more machinery.
- `/stark-gh:pr-merge [--pr N] [...]` — rebase + draft squash prose & CHANGELOG entry via Codex + force-push + **mark a draft PR ready-for-review** (fires the target CI) + squash-merge once CI is green
- `/stark-gh:cleanup [--pr N] [--dry-run] [--keep-branch NAME] [--no-rebase] [--no-watcher-cleanup] [--no-config] [--no-gc] [--drop-stale-stashes] [--force] [--json]` — sweep merged/stale branches (local + remote), prune tracking refs, remove worktree leftovers (including detached-HEAD `review-*-prN-*` worktrees for done PRs), clean merged-PR watcher state, surface stale stashes, `git gc` loose objects, and rebase current branch onto upstream so history stays linear. `--pr N` narrows to one PR's head ref + watcher state.
- `/stark-review [PR_NUMBER]` — single-agent PR code review (1 LLM × triage-selected domains from 5, fast/cheap; triage skips low-confidence domains entirely — skipped is logged, never posted). The fix-loop test gate's `test_command` is **auto-detected** when unset: `stark_review_lib.ts::detectTestCommand()` reads the **trusted** `--config-root` checkout only (never the PR worktree — RCE guard) and recognizes Makefile `test:`/`npm test`/`go test`/`cargo test`/node:test `*.test.ts|js`/pytest-with-tests; resolution order is explicit `config.test_command` → detected → none (soft-skip via `allow_no_test_command`). Repos no longer pin a brittle `test_command` (the old `pytest scripts/` left from the Python era exited 5 every run). **Playground-scope guard:** the per-agent review preamble (`global/prompts/{claude,codex,gemini}/agent.md`, prepended to all 5 domains) carries the scope-proportionality block — a declared single-user/playground project is not held to auth/RBAC/HA/audit-log/migration/adversarial-input/exhaustive-test standards; real defects (crash/data-loss/wrong-output/broken-contract/scope-relevant-security) always stay in scope. Stops junk "add production hardening" comments on playground PRs.
- `/stark-review-improvement [--prompts-dir DIR]` — improve prompts based on review assessment (PR or spec/plan review)
- `/stark-terraform-review [path] [--agents a,b] [--changed] [--no-tools] [--min-severity ...] [--pr N --repo O/R] [--dry-run] [--json]` — **multi-agent** Terraform/OpenTofu (HCL) review against a path: runs the failure-mode rubric across one or more configurable LLMs (each its own subagent), merges + cross-validates findings. Host runs read-only scanners (`terraform fmt/validate`, `tflint`, `trivy config`, `checkov`) as evidence. Thin skill → dispatcher `tools/iac_review.ts --kind terraform`; rubric in `global/prompts/iac-review/terraform.md` (version-aware guard included). Agents resolve `--agents` > config `iac_review.agents` > `["codex"]`. Rules adapted from HashiCorp Style Guide (MPL-2.0) + Anton Babenko terraform-skill (Apache-2.0) + TerraShark; research in `docs/specs/2026-06-24-terraform-terragrunt-review-research.md`.
- `/stark-terragrunt-review [path] [--agents a,b] [--changed] [--no-tools] [--min-severity ...] [--pr N --repo O/R] [--dry-run] [--json]` — **multi-agent** Terragrunt **orchestration-layer** review (include/dependency/generate/remote_state, mock-output schema, DAG cycles, values/DRY, state isolation, stack composition, git source refspec). Host scanners: `terragrunt hcl validate`, `terragrunt find --dag --dependencies`. Defers resource/module HCL to `/stark-terraform-review`. Thin skill → `tools/iac_review.ts --kind terragrunt`; rubric in `global/prompts/iac-review/terragrunt.md`. Same configurable `iac_review.agents`. Adapted from jfr992/terragrunt-skill (Apache-2.0) + TerraShark.

### Workflow & Ops

- `/stark-fresh-eyes <doc-path> [--focus "aspect"] [--model opus|fable]` — **one-shot zero-context review of a prompt/brief/spec/doc before it ships.** Dispatches ONE read-only subagent (Fable by default) with zero shared context that re-verifies every checkable claim by a **DIFFERENT method** than the doc's own (recount recursively, recompute numbers from raw sources, test paths, `--help` cited commands) and reports defects only — wrong facts with measurements, contradictions, two-reading ambiguities, unresolvable references, cannot-verify claims, missing definitions. **One dispatch per document revision, findings dispositioned once (fix/reject/accept-as-known), never a round 2** — fresh eyes work through method difference, not repetition (the 39-vs-34 file-count lesson; LLM-review loops are non-convergent per the 2026-07-25 autopsy). Zero findings is a valid output. Pure protocol skill, zero TS. Skill `skill/stark-fresh-eyes/SKILL.md`.
- `/stark-ssot [file-or-area]` — **SSOT consolidation workflow**: give a duplicated value/rule/calculation ONE owner and route the copies through it (discover the repo's existing owners first — config/registry/resolver/domain module; unify only when both places answer the same question; record deliberate duplication + its drift guard). **Detection vs workflow:** automated SSOT detection in PR review lives inside the `spec-conformance` domain (triage-selected) since the 2026-07-26 prompt rewrite — the standalone auto-fired `ssot` lens was retired after producing 18 of the fleet's 28 review-noise labels (45% noise; its 22 real fixes all had a nameable owner). The skill's review bar mirrors the domain's: an SSOT finding names BOTH sides (copy + existing owner, quoted) plus the concrete drift scenario; **no nameable owner → not a finding**. Skill `skill/stark-ssot/SKILL.md`.

- `/stark-session [start|end]` — session management: briefing on start, cleanup on end
- `/stark-handover [save|resume|status] [--task slug]` — cross-`/clear` session continuity: **save** mines the conversation into the next `handover_{N}.md` (numbered chain, frontmatter-linked `prev`) and rewrites the `PROGRESS.md` done-vs-todo tracker under `~/Code/Handovers/{project}/{worktree}/{task}/`; **resume** loads the latest handover + tracker in one call so a fresh session continues with zero recap; **status** lists tasks. ## Conventions

- Prompts are per-agent: each LLM gets its own version of each domain
- Domain IDs are slugs derived from filenames: `01-architecture.md` → `architecture`
- Config uses JSON, prompts use markdown
- Agent preambles in `agent.md`, domain prompts in `NN-domain.md`
- **Every skill honors `--help`.** Each `skill/*/SKILL.md` opens with a `## Help` block right after its frontmatter that points at the shared `standards/help.md` protocol: a standalone `--help`/`-h`/`help` token in `$ARGUMENTS` prints the skill's purpose + usage + `## Arguments` and stops (no preflight, no phases, side-effect-free). The `skill_smoke_test.test.ts` guard asserts every skill references `standards/help.md`.
